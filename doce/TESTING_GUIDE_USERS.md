# دليل الاختبار السريع - User Management Testing Guide

## 🚀 اختبار سريع لجميع الإصلاحات

### المتطلبات المسبقة
- تأكد من تشغيل السيرفر: `php artisan serve`
- تأكد من تسجيل الدخول كمسؤول (Administrator)
- افتح أدوات المطور في المتصفح (F12) لمراقبة الأخطاء

---

## 1️⃣ اختبار صفحة التعديل (Edit Page)

### الخطوات:
```
1. اذهب إلى: /users
2. انقر على زر "تعديل" (أيقونة القلم) لأي مستخدم
3. انتقل إلى تبويب "المعلومات الأساسية" (Basic Info)
```

### ما يجب التحقق منه:

#### ✅ حالة المستخدم (Account Status):
```html
<!-- يجب أن ترى -->
<div class="toggle-checkbox" id="is_active">
- إذا كان المستخدم نشطاً: checkbox عليها checked
- إذا كان غير نشط: checkbox بدون checked
</div>
```

**الاختبار:**
- [ ] الحالة المعروضة تطابق الحالة الفعلية للمستخدم
- [ ] يمكن النقر على المربع لتبديل الحالة
- [ ] عند النقر خارج المربع (على البطاقة)، يتغير أيضاً
- [ ] الحفظ يعمل بشكل صحيح

#### ✅ حالة التحقق من البريد (Email Verification):
```html
<!-- يجب أن ترى -->
<div class="toggle-checkbox" id="email_verified">
- إذا كان verified: checkbox عليها checked
- إذا كان unverified: checkbox بدون checked
</div>
```

**الاختبار:**
- [ ] الحالة المعروضة تطابق الحالة الفعلية
- [ ] يمكن التبديل بين الحالات بسهولة
- [ ] الحفظ يعمل بشكل صحيح

## 2️⃣ اختبار صفحة الإنشاء (Create Page)

### الخطوات:
```
1. اذهب إلى: /users
2. انقر على "إضافة مستخدم جديد"
3. انتقل إلى تبويب "المعلومات الأساسية"
```

### ما يجب التحقق منه:

```
is_active: يجب أن يكون checked افتراضياً
email_verified: يجب أن يكون checked افتراضياً
```

**الاختبار:**
- [ ] كلا الخيارين مفعلان افتراضياً
- [ ] يمكن إلغاء تفعيل أي منهما
- [ ] يمكن إعادة تفعيلهما
- [ ] إنشاء المستخدم يحفظ الحالات بشكل صحيح

## 3️⃣ اختبار الصفحة الرئيسية (Index Page) - AJAX Toggles

### الخطوات:
```
1. اذهب إلى: /users
2. ابحث عن مستخدم في الجدول
3. جرب تبديل "الحالة" (Status Toggle)
```

### ما يجب التحقق منه:

#### ✅ تصميم التبديل الجديد:
```
يجب أن ترى:
- Toggle switch بتصميم دائري حديث
- Label أسفل يوضح الحالة الحالية
- ألوان مختلفة للحالات (أخضر للنشاط، أصفر للتحقق)
```

#### ✅ مودال التأكيد:

**عند النقر على التبديل:**
```
1. يظهر مربع حوار (Modal) للتأكيد
2. يعرض اسم المستخدم
3. يعرض الإجراء المطلوب (تغيير الحالة إلى: نشط/غير نشط)
4. زران: "إلغاء" و "تأكيد"
```

**الاختبار:**
- [ ] المودال يظهر بشكل صحيح
- [ ] النص يعرض المعلومات الصحيحة
- [ ] زر "إلغاء" يغلق المودال ويعيد الحالة الأصلية
- [ ] زر "تأكيد" ينفذ التغيير

#### ✅ تحديث AJAX:

**بعد تأكيد التبديل:**
```
1. يتم إرسال طلب POST إلى السيرفر
2. لا يتم إعادة تحميل الصفحة
3. يتغير لون التبديل فوراً
4. يتغير النص أسفل التبديل
5. يظهر إشعار نجاح (Toast)
```

**الاختبار:**
- [ ] الصفحة لا تعاد تحميلها
- [ ] التبديل يتغير لونه بنعومة
- [ ] النص يتحدث باللغة الصحيحة (عربي/إنجليزي)
- [ ] إشعار النجاح يظهر لمدة 3 ثواني
- [ ] بعد عمل Refresh، الحالة الجديدة محفوظة

#### ✅ معالجة الأخطاء:

**لمحاكاة خطأ:**
```javascript
// في Console المتصفح، عطل الشبكة مؤقتاً
// أو قم بتعديل URL في الكود ليصبح خاطئاً
```

**يجب أن يحدث:**
```
1. يظهر إشعار خطأ
2. يعود التبديل إلى حالته الأصلية
3. لا يتغير أي شيء في قاعدة البيانات
```

**الاختبار:**
- [ ] عند فشل الطلب، يعود التبديل لحالته الأصلية
- [ ] يظهر إشعار خطأ أحمر اللون
- [ ] يمكن محاولة التبديل مرة أخرى

## 4️⃣ اختبار تبديل حالة التحقق (Verification Toggle)

### الخطوات:
```
1. في نفس صفحة /users
2. ابحث عن عمود "Verification Toggle"
3. جرب تبديل حالة التحقق
```

### ما يجب التحقق منه:

**نفس سلوك تبديل الحالة مع الفروق:**
```
- اللون الأصفر/البرتقالي للتحقق
- النص: "Verified" / "Unverified"
- يؤثر على email_verified_at في قاعدة البيانات
```

**الاختبار:**
- [ ] نفس سلوك toggle الحالة
- [ ] اللون الأصفر يُستخدم للتحقق
- [ ] النص يتحدث بشكل صحيح
- [ ] التحديث ينعكس على قاعدة البيانات

## 5️⃣ اختبار قائمة المراقبة (Console Monitoring)

### افتح Console المتصفح (F12):

#### عند التحميل الأولي:
```
👤 [UserMgr] [XX:XX:XX] [INFO] 🚀 Booting UserManager Professional Module...
👤 [UserMgr] [XX:XX:XX] [SUCCESS] ✨ UserManager ready and operational.
```

#### عند تبديل الحالة:
```
👤 [UserMgr] [XX:XX:XX] [DEBUG] Tab Activated: basic
👤 [UserMgr] [XX:XX:XX] [SUCCESS] Toggle updated successfully
```

#### عند حدوث خطأ:
```
👤 [UserMgr] [XX:XX:XX] [ERROR] 💥 Toggle failed: {...}
```

**الاختبار:**
- [ ] لا توجد أخطاء حمراء في Console
- [ ] رسائل الـ Log تظهر بشكل صحيح
- [ ] يمكن تتبع العمليات من خلال الـ Logs

## 6️⃣ اختبار Network Requests

### افتح Network Tab في المتصفح:

#### عند تبديل الحالة:
```
Request URL: /users/{id}/toggle-status
Request Method: POST
Status Code: 200 OK

Request Payload:
{}

Response:
{
    "success": true,
    "is_active": true/false,
    "message": "تم تحديث الحالة بنجاح"
}
```

**الاختبار:**
- [ ] Request يُرسل بشكل صحيح
- [ ] Response يحتوي على success: true
- [ ] الرسالة مناسبة
- [ ] Headers تحتوي على CSRF Token

## 7️⃣ اختبار الصلاحيات (Permissions)

### كمستخدم غير Administrator:

```
1. سجل الدخول بمستخدم عادي
2. حاول الوصول إلى صفحة المستخدمين
3. حاول تبديل الحالات
```

**يجب أن يحدث:**
```
- لا تظهر التبديلات للمستخدمين العاديين
- تظهر فقط badges ثابتة للحالة
- لا يمكن الوصول إلى صفحات التعديل
```

**الاختبار:**
- [ ] المستخدم العادي لا يرى التبديلات
- [ ] يرى فقط labels ثابتة
- [ ] لا يمكنه إجراء AJAX requests

## 🐛 مشاكل شائعة وحلولها

### مشكلة 1: التبديل لا يعمل
```
السبب المحتمل: CSRF Token مفقود
الحل: تأكد من وجود <meta name="csrf-token"> في <head>
```

### مشكلة 2: المودال لا يظهر
```
السبب المحتمل: Tailwind Modal API غير محملة
الحل: تأكد من تحميل scripts بشكل صحيح
```

### مشكلة 3: AJAX request يفشل
```
السبب المحتمل: Route غير معرف
الحل: تحقق من routes/web.php
```

### مشكلة 4: الحالة لا تتغير في قاعدة البيانات
```
السبب المحتمل: Policy تمنع التعديل
الحل: تحقق من UserPolicy والصلاحيات
```
